## Planning Implications

- [DECISION] The feature PRD must define inspection, dry-run reporting, cleaned-copy behavior, explicit confirmation for in-place changes, and honest unsupported-path reporting.
- [DECISION] Voice DNA remains the primary trust boundary. Any text rewrite must load `STYLE-GUIDE.md` first and preserve fresh context per atomic unit.
- [DECISION] Architecture must preserve the dependency-free package and use optional external CLIs only through capability detection and explicit command instructions.
- [DECISION] The implementation must not claim that cleaned content is human-written, undetectable, or free of all provenance signals.
- [DECISION] Verification should include targeted Node tests, `npm test`, and `npm run policy:check` once the feature is implemented.

## Risks And Unknowns

- [HYPOTHESIS] Unicode provenance inspection and metadata cleaning create new trust boundaries around data loss, disclosure truth, and destructive in-place edits.
- [HYPOTHESIS] Statistical watermark reduction can alter writer voice unless rewrite behavior is opt-in and routed through Voice DNA.
- [HYPOTHESIS] Container metadata, C2PA, EXIF, and image watermark capabilities vary by installed external tools and file type.
